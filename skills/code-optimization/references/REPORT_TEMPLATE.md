### Quick Wins (priority — address before next release)

#### O001 — N+1 query in `GET /users` endpoint

| Axis       | Value                                                      |
| ---------- | ---------------------------------------------------------- |
| **Impact** | High — adds 50ms p99 per request, 10× DB load              |
| **Risk**   | SAFE — same response shape                                 |
| **Effort** | S (< 1h)                                                   |
| **Confidence** | High                                                   |

**File:** `api/users.py:42`

**Code (verbatim):**
\`\`\`python
@router.get("/users")
def list_users(db: Session = Depends(get_db)):
    users = db.query(User).all()
    return [{"id": u.id, "profile_name": u.profile.name} for u in users]
\`\`\`

**Why this is High Impact:**
- The list comprehension touches `u.profile` for each user, triggering a separate `SELECT * FROM profiles WHERE user_id=?` per row.
- With 200 users in the test DB, this is 201 queries instead of 2 (~50ms p99 measured in the team's own perf dashboard, captured in `monitoring/dashboards/api-latency.json`).

**Suggested fix (SAFE):**
\`\`\`python
@router.get("/users")
def list_users(db: Session = Depends(get_db)):
    users = db.query(User).options(selectinload(User.profile)).all()
    return [{"id": u.id, "profile_name": u.profile.name} for u in users]
\`\`\`

**Validation:**
- context7 `/sqlalchemy/sqlalchemy` §loading.html — `selectinload` is documented as the antidote to N+1 with one-to-many relationships.

**Verification:**
- Add a pytest assertion using `event.listen(Engine, "before_cursor_execute", counter)` to assert ≤ 2 queries.

**Cross-link:** none.

| **Risk**   | REVIEW — middleware change, affects all JSON responses     |

**File:** `api/main.py:18`

**Code (verbatim):**
\`\`\`python
app = FastAPI()  # default JSONResponse uses stdlib `json`
\`\`\`

**Why this is High Impact:**
- py-spy flamegraph (`/tmp/profile.svg` from Phase 2) shows 18% of CPU time in `json.dumps`.
- `orjson` is 2–3× faster on dict-heavy payloads and emits identical output for the response shapes here.

**Suggested fix (REVIEW):**
\`\`\`python

app = FastAPI(default_response_class=ORJSONResponse)
\`\`\`

**Validation:**
- WebSearch: https://fastapi.tiangolo.com/advanced/custom-response/#orjsonresponse — official recommendation for high-throughput APIs.

**Verification:**
- Re-run py-spy load test and confirm `json.dumps` falls below 5% in flamegraph.
- Diff response bodies on a sample of endpoints to confirm byte-identical for the schemas in use.

## 2. Schema rules

- **One H3 per finding.** Format: `#### <ID> — <title>` (Quick Wins / Strategic / Polish) or row in table (Deferred / Dropped).
- **ID format:** `O<NNN>` zero-padded. Auto-increment within a single run; restart at `O001` per run (no cross-run persistence).
- **Code blocks must quote verbatim** with the file name and line range hinted, but the content matches the file at the cited line byte-for-byte.
- **Validation field is required for `Impact >= High AND Confidence < High`** unless `--no-validate` was set; otherwise it may say `Validation: not required`.
- **Cross-link line is required** when the finding overlaps another skill's domain (security, debugging, refactor mechanics, CI gate).
- **Mermaid diagrams are not used.** Tables only. The report is meant to be read in any markdown renderer + on GitHub PR diffs.

## 3. Anti-patterns to avoid in the report

- **Inventing latency numbers** without a profile or doc citation.
- **Mixing fix risk with bug risk** in the Risk axis.
- **Inflating Effort** to make a Quick Win look Strategic (or vice-versa).
- **Padding** with "consider X" findings that have no code citation.
- **Duplicating findings** across quadrants — assign each finding to exactly one quadrant.
